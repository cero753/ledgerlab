RL environment · verifiable rewards · finance

ledgerlab

An environment where an agent receives a financial model with seeded analyst errors and has to repair it through tools. The grader re-runs the agent's model under perturbed assumptions, so the only way to score is to actually fix it.

github.com/cero753/ledgerlab Kartik Bhardwaj

Why spreadsheet debugging

On SpreadsheetBench 2 (arXiv 2606.29955) the best model reaches 34.9% overall and 12% on debugging. Debugging is everyday analyst work and it is checkable, which makes it a good target for RL. A benchmark has a fixed task set. An environment needs an unlimited supply of fresh tasks, a dense reward that cannot be gamed, and fast verification. ledgerlab is built around those three requirements.

Architecture

model.py · bugs.py

Generator

A seeded company: three revenue segments, P&L, unlevered FCF, DCF, and a Notes sheet with the signed-off assumptions. Rows are filled right like an analyst drags a formula, so anchoring errors behave as they do in Excel. 21 error types across four tiers.

task.py

Task QC

A task is redrawn unless every error moves a key output, fixing any one error still moves an output with the others present, the model evaluates cleanly, and each error follows from the Notes.

rewards.py

Verifier

Each changed cell is dropped into the golden model and must match under the nominal inputs and three random perturbations of every assumption. Any correct formula passes. A typed number fails as soon as the inputs move.

workbook.py

Formula engine

Recursive-descent parser and memoised evaluator in pure Python: strings, comparisons, IF/IFERROR, SUMIFS/COUNTIFS, dates. Deterministic, no Excel or LibreOffice, TODAY() frozen.

reward = integrity × (0.7 × fixed_fraction + 0.3 × solved)   integrity = max(0, 1 − 0.25 × damaged_cells)

Baselines and calibration

Claude Haiku, Sonnet and Opus, run headless through the MCP server with no file access, scored 1.00 on every easy, medium and hard task (3–4 tasks per model per tier). A saturated environment gives no learning signal, so I looked at why. Rows are uniform and each error broke one column, so the broken cell was the odd one out; the line-by-line spec turned the task into a diff.

The expert tier targets that shortcut: errors that span a whole row, approved pattern breaks that must be left alone, and a brief with assumptions and conventions instead of a spec. Haiku and Sonnet still scored 1.00 but needed 60–70% more tool calls. The next real increase in difficulty comes from larger, messier, expert-built workbooks, which is what the bring-your-own mode is for.

Bring your own workbook

Any correct .xlsx becomes a source of graded repair tasks. Inputs (constants that formulas read) and outputs (formulas nothing reads) are detected or supplied, errors are seeded close to the outputs, and the same QC and verifier apply. On a real 7-sheet workbook with 10,300 formulas: 100% of formulas evaluated, a 3-error task built in 32 s.

uv run ledgerlab byo model.xlsx --check
uv run ledgerlab byo model.xlsx --bugs 3 --seed 0 --reveal

Run it

git clone https://github.com/cero753/ledgerlab && cd ledgerlab
uv sync
uv run pytest                     # 71 tests
uv run ledgerlab redteam          # reward table above
uv run ledgerlab export --seed 1007 --difficulty hard --out task.xlsx --reveal

# play it with Claude Code
uv sync --extra mcp
claude mcp add ledgerlab -- uv run --directory "$PWD" --extra mcp ledgerlab-mcp

Python 3.12+, one runtime dependency (openpyxl), no GPU. About 140 scripted episodes per second per core; a full grade takes about half a millisecond.

Limits

  • One model template. LBO and three-statement templates are next.
  • The error taxonomy is mine, not calibrated against how often analysts make each mistake.
  • A formula that is right only when two inputs happen to match could pass random perturbation; targeted scenario search would close that gap.
  • The engine is not full Excel. VLOOKUP, INDEX/MATCH and array formulas are not supported yet, and byo --check lists the cells it cannot evaluate.
